Chapter 4 Reference

How to Trace a Parser

Recursive-Descent (Top-Down / LL)

One function per nonterminal. The parser starts at the root and expands leftmost nonterminals using the current lookahead token. Convention: when a function returns, nextToken holds the next unread token.

  1. Call the top-level function (e.g., expr()).
  2. Look at nextToken to decide which RHS to expand (pairwise disjointness must hold).
  3. For each terminal in the chosen RHS: call lex() to consume it and advance.
  4. For each nonterminal in the RHS: call its function recursively.
  5. EBNF {…} repetition → a while loop checking the lookahead. EBNF […] optional → an if.
  6. If nextToken doesn't match any valid first symbol → call error().

Key restriction: grammar must not be left-recursive and must pass the pairwise disjointness test (FIRST sets of each alternative must be disjoint).

Shift-Reduce (Bottom-Up / LR)

Works left-to-right, building the parse tree from leaves to root. Uses a stack of grammar symbols + states, an ACTION table (terminals), and a GOTO table (nonterminals after a reduce).

  1. Begin with stack = 0, input = full token string + $.
  2. Look up ACTION[top-state][next-token]:
    • Shift Sn — push token + state n onto the stack; advance input.
    • Reduce Rk — pop |RHS| symbols, push LHS nonterminal; look up GOTO[exposed-state][LHS] to get the new state and push it.
    • Accept — parse complete.
    • Error — syntax error.
  3. After every reduce, the handle (leftmost simple phrase = what was just popped) is replaced by its LHS.
  4. Continue until Accept or Error.

Key insight (Knuth): the state on top of the stack encodes the entire parse history — no need to inspect deeper stack contents.
