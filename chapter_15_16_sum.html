Chapter 15

Functional Programming Languages

Based on mathematical functions. No variables, no assignment, no state. Execution via function application, recursion, and conditional expressions.

Chapter 16

Logic Programming Languages

Based on predicate calculus. Programs are facts + rules. Execution via resolution and unification — declarative, not procedural.

Key contrast

Paradigm Comparison

Imperative: how to compute. Functional: what functions produce. Logic: what the result looks like — the system figures out how.

Languages

Functional Language Profiles

Language Genealogy

Lisp 1959 — John McCarthy, MIT

First functional language. Atoms & lists. Typeless. S-expressions for code & data. Dynamic scoping (early). EVAL as accidental interpreter. Still dominant in AI.

Scheme mid-1970s — Sussman & Steele, MIT

Small, clean Lisp dialect. Static scoping exclusively. First-class functions. Tail recursion required. Educational & research language.

Common Lisp early 1980s — standardization effort

Union of Lisp dialects. Large & complex. Both static and dynamic scoping. Macros (DEFMACRO, reader macros). CLOS for OOP. Commercial AI use.

ML Milner et al., Edinburgh

Static scoping, strong typing, type inference. Infix notation. Pattern matching. Exception handling. Spawned Haskell, Caml, OCaml, F#.

Haskell descended from ML & Miranda

Pure FP (no side effects). Lazy/nonstrict evaluation. Infinite lists. List comprehensions. Function overloading (unlike ML). Strongly typed with inference.

F# .NET era — OCaml-based

OCaml descendant. Functional + imperative + OOP. Full .NET interop and IDE. Pipeline |> and composition >>. Lazy sequences. Currying supported.

TermDefinitionKey Detail
PropositionA logical statement that may or may not be true; consists of objects and relationshipsCan be stated as a fact (assumed true) or as a query (truth to be determined)
Atomic PropositionA single compound term: functor + ordered parameter liste.g., man(jake), likes(bob, steak); no intrinsic semantics
Compound TermTwo parts: a functor (names the relation) + ordered parameter listRepresents an element of a mathematical relation (table row)

Clausal FormStandard proposition form: B1∪…∪Bn ⊂ A1∩…∩Am — if all A's true, then at least one B is trueAntecedent (right/if part) → Consequent (left/then part); all props can be converted to clausal form
Horn ClauseRestricted clausal form: either a single atomic prop on the left (headed) or empty left side (headless)Headed = rules; Headless = facts; restriction makes resolution practical; named after Alfred Horn (1951)
ResolutionAn inference rule for deriving new propositions from given ones in clausal formDiscovered by Alan Robinson (1965, Syracuse); basis of Prolog's inferencing; refutation-complete
UnificationProcess of finding variable instantiations that allow propositions to match during resolutionVariables temporarily bound to values; if match fails, backtracking may try other values
InstantiationTemporary assignment of a value to a variable during resolutionLasts only for the duration of one goal proof; uninstantiated variables are free
BacktrackingWhen a subgoal fails, the system backs up and tries alternate solutions for the previous subgoalCore to Prolog; can be costly (time/space); controlled with the cut operator
Forward ChainingBottom-up resolution: start from facts, work toward goalBetter when many candidate answers exist; Prolog does NOT use this
Backward ChainingTop-down resolution: start from goal, work backward to find supporting factsProlog uses this; better for small candidate answer sets
Depth-First SearchProve first subgoal completely before moving to next; Prolog's approachUses less memory than breadth-first but can loop; requires careful DB ordering
Declarative SemanticsEach statement's meaning is determined from the statement itself, independent of how it's usedFar simpler than imperative semantics; no need to trace execution or know state
Closed-World AssumptionIf a goal cannot be proved true from the database, Prolog assumes it is falseProlog is true/fail, not true/false; cannot prove negation — only assumes it when proof of positive fails
Cut Operator (!)A goal that always succeeds but prevents backtracking past itSide effect: subgoals to its left cannot be re-satisfied; compared to goto in imperative languages
Nonprocedural ProgrammingSpecify characteristics of the result, not how to compute itThe system determines HOW; pure logic programming ideal; Prolog only partially achieves this due to cut, ordering

FP vs. Imperative — Extended Comparison (§15.11)

Functional Advantages

  • Simpler syntax: list structure used for both code and data (Lisp)
  • Simpler semantics: no side effects, no need to track state
  • Smaller programs: 4–10× smaller than imperative counterparts (claimed)
  • Easier testing: functions tested in isolation; referential transparency
  • Natural concurrency: pure functions have no shared mutable state; actual parameter expressions can often be evaluated in parallel
  • Less mental overhead: no need to track program state at each step

Functional Disadvantages

  • ~2× slower execution than compiled imperative programs on average
  • Lazy evaluation adds semantic complexity and slows execution further
  • Designed on mathematical functions, not von Neumann architecture → less hardware advantage
  • Difficult to learn for programmers trained on imperative languages
  • Early implementations were interpreted → poor performance reputation
  • "Lines of code" productivity metric is misleading; not all lines equal in complexity

Quiz Prep

High-Probability Exam Questions

Study tip: These are drawn directly from the Review Questions sections at the end of each chapter and core concepts that appear repeatedly in the text.
Chapter 15 — Functional Programming
  • Q1

    What is referential transparency? A function always produces the same result for the same arguments, regardless of context. Possible because pure FP has no side effects and no global state.

  • Q2

    What does a lambda expression specify? A nameless function — its parameters and a mapping expression. Devised by Alonzo Church (1941). Written λ(x)expression.

  • Q3

    Why is QUOTE needed in Scheme? Scheme code and data have the same form. Without QUOTE, EVAL would try to evaluate a list parameter as a function call. QUOTE returns its argument without evaluating it.

  • Q4

    What are the two forms of DEFINE? (1) (DEFINE symbol expression) — binds a name to a value (like a named constant). (2) (DEFINE (name params) expression) — defines a named function (abbreviated LAMBDA binding).

  • Q5

    Why are CAR and CDR so named? First Lisp ran on IBM 704, whose memory words had "address" and "decrement" fields. CAR = Contents of Address part of Register; CDR = Contents of Decrement part of Register. Used to store the two pointers of a list node.

  • Q6

    What is tail recursion and why does it matter? A function is tail recursive if its recursive call is the LAST operation. The return value of the recursive call IS the function's return value. Scheme requires tail recursive functions to be converted to iteration → O(1) stack space instead of O(n).

  • Q7

    What are the differences between EQ?, EQV?, and EQUAL? EQ? = pointer equality (reliable only for symbolic atoms). EQV? = value equality for both symbolic and numeric atoms (slower). EQUAL? = deep structural equality including lists (slowest). Use EQ? or = when you know the type; use EQV? for mixed; EQUAL? only when type is unknown.

  • Q8

    What is currying? What is partial evaluation? Currying replaces a multi-parameter function with a chain of single-parameter functions. Partial evaluation evaluates a curried function with fewer args than it takes, producing a new function that takes the rest. e.g., add 5 → a function that adds 5 to any number.

  • Q9

    What is lazy evaluation and which language uses it? Expressions are evaluated ONLY when their values are needed. Haskell uses lazy (nonstrict) evaluation. Allows infinite data structures (e.g., [0..]). Contrasts with strict evaluation (Scheme, ML, most others) where all params are evaluated before function call.

  • Q10

    Two fundamental ways ML differs from Scheme? (1) ML is strongly typed with type inference; Scheme is essentially typeless. (2) ML uses infix notation for arithmetic; Scheme uses prefix S-expression notation for everything.

  • Q11

    Three characteristics making Haskell different from ML? (1) Haskell functions can be overloaded; ML cannot. (2) Haskell uses nonstrict/lazy semantics; ML uses strict. (3) Haskell is a pure functional language (no side effects); ML allows some side effects (mutable arrays).

  • Q12

    What is a higher-order function? Give examples. A function that takes functions as parameters OR returns a function OR both. Examples: map (applies function to each list element), filter (returns elements satisfying predicate), compose/∘ (chains two functions), curry (returns new function).

  • Q13

    Why can concurrency be easier with functional languages? Pure functions have no side effects and don't depend on global/nonlocal variables — they are independent. Actual parameter expressions can often be evaluated concurrently. Shared immutable data needs no synchronization. The programmer needn't manually partition the program into threads.

Chapter 16 — Logic Programming
  • Q14

    What are the three primary uses of symbolic logic in formal logic? (1) Express propositions. (2) Express relationships between propositions. (3) Describe how new propositions can be inferred from propositions assumed to be true.

  • Q15

    What are the two parts of a compound term? A functor (the function symbol naming the relation) and an ordered parameter list. e.g., in likes(bob, steak): functor = likes, params = bob, steak.

  • Q16

    What are Horn clauses and what are their two forms? Horn clauses are restricted clausal form propositions. (1) Headed Horn clause: single atomic prop on left side — used for RULES. (2) Headless Horn clause: empty left side — used for FACTS. Named after Alfred Horn (1951). Restriction makes resolution practical.

  • Q17

    Define resolution and unification. Resolution: an inference rule that derives new propositions from given ones in clausal form (Robinson, 1965). Unification: the process of finding variable instantiations that allow two propositions to match during resolution. Instantiation = temporarily assigning a value to a variable.

  • Q18

    What is the basic concept of declarative semantics? Each statement's meaning can be determined from the statement itself alone, without knowing context or execution history. Dramatically simpler than imperative semantics, which requires knowing scoping rules, variable types, and execution history to interpret a statement.

  • Q19

    What is wrong with K is K + 1 in Prolog? If K is uninstantiated, the right side reference is undefined → clause fails. If K IS already instantiated, the left side cannot be re-instantiated → clause fails. The is operator requires right side fully instantiated AND left side uninstantiated. Unlike assignment, it cannot update a value.

  • Q20

    Explain the closed-world assumption. Why is it a limitation? If Prolog cannot prove a goal is true from its database, it assumes the goal is FALSE. Prolog is true/fail, not true/false — it cannot actually prove things false, only that it cannot prove them true. This can give misleading results; things genuinely unknown appear false.

  • Q21

    Explain the negation problem in Prolog. Prolog's not(X) succeeds if resolution cannot prove X — it is NOT logical negation. not(not(goal)) ≠ goal in Prolog. When not's argument fails, all its variables are uninstantiated, so the outer not returns without useful variable bindings. Caused by Horn clause form: positive logic → only positive conclusions possible.

  • Q22

    What is the difference between forward and backward chaining? Forward chaining (bottom-up): start from facts in DB, work toward the goal. Better when many potential answers exist. Backward chaining (top-down): start from goal, work backward to find supporting facts. Prolog uses this. Better for small candidate answer sets.

  • Q23

    What is the cut operator and why is it compared to goto? ! always succeeds but prevents backtracking past it — subgoals to its left cannot be re-satisfied. Used to improve efficiency (generate-and-test, set membership). Compared to goto because it introduces explicit control flow into declarative programs, undermining the nonprocedural principle of logic programming.

  • Q24

    How does Prolog's append differ from Scheme's append? Prolog's append is a PREDICATE — it returns yes/no, not a list. The result list is bound to its 3rd parameter. It's also more flexible: can be used in reverse (append(X, Y, [a,b,c]) finds all ways to split [a,b,c] into two lists). Scheme's append returns a new list (a value).

    What are the three major application areas of logic programming? (1) Relational DBMS — tables as facts, relationships as rules, queries as goals. (2) Expert systems — knowledge base + inference rules + goal queries. (3) Natural-language processing — LP equivalent to context-free grammars; backward chaining ≡ parsing.
