7.2
Arithmetic Expressions
// precedence · associativity · side effects · referential transparency
Operator Types

Arithmetic expressions consist of operators, operands, parentheses, and function calls. Operators are classified by how many operands they take:

Unary — one operand. Usually prefix (e.g. -a, ++count)
Binary — two operands. Usually infix (e.g. a + b). Most common.
Ternary — three operands. The ? : conditional in C-based languages.
Example
-a          // unary, prefix
a + b       // binary, infix
a ? b : c   // ternary
Operator Precedence

Precedence defines which operator is evaluated first when operators of different levels appear together. Standard hierarchy (most languages):

Highest: Exponentiation **
Middle: * / %
Lowest: + -
Example
a + b * c
// b*c is evaluated first due to higher precedence of *
// Result is NOT (a+b)*c
Special Case
APL has a single level of precedence for ALL operators — order is determined entirely by associativity (right to left).
Operator Associativity

When operators have equal precedence, associativity decides evaluation order.

Most operators → Left to right: a - b + c = (a - b) + c
Exponentiation → usually Right to left: A ** B ** C = A ** (B ** C)
Exception: Visual Basic's ^ exponentiation is left associative
APL: ALL operators are right to left
Example — APL
A × B + C   // In APL, evaluated right to left
            // + is done first, then ×
            // If A=3,B=4,C=5 → 3×(4+5) = 27
Parentheses (7.2.1.3)

Parentheses let programmers override precedence and associativity rules. A parenthesized subexpression has precedence over adjacent unparenthesized parts.

Example
(A + B) * C   // addition first, despite * having higher precedence
(A + B) + (C + D)  // can prevent overflow in edge cases
Note
APL's designer Ken Iverson chose to rely entirely on parentheses and right-to-left associativity — no precedence rules at all. Simple to learn but tedious to write and hard to read.
Ruby Expressions (7.2.1.4)

Ruby is a pure object-oriented language — every value including literals is an object. All arithmetic, relational, and assignment operators are implemented as methods.

a + b is actually a call to the + method of object a, passing b as a parameter
Since operators are methods, they can be overridden by application programs
Contrast: C++ vs Ruby
// C++ — operators implemented as function calls
// Ruby — operators implemented as object methods (overridable)
Expressions in Lisp (7.2.1.5)

In Lisp, ALL operations are performed by subprograms that must be explicitly called. There are no infix operators.

Example — a + b*c in Lisp
(+ a (* b c))
// First element = function name
// Remaining elements = parameters
Conditional Expressions (7.2.1.6)

The ternary operator ? : in C-based languages allows inline conditional assignment. Both clauses are mandatory.

Example
// Instead of:
if (count == 0)
    average = 0;
else
    average = sum / count;

// Write:
average = (count == 0) ? 0 : sum / count;
Languages
C-based languages, Perl, JavaScript, Ruby all support conditional expressions.
Operand Evaluation Order & Side Effects (7.2.2.1)

A functional side effect occurs when a function changes one of its parameters or a global variable. When side effects exist, operand evaluation order affects the result.

Classic Example
int a = 5;
int fun1() {
    a = 17;        // side effect: changes global a
    return 3;
}
void main() {
    int b = a + fun1();
    // If a evaluated first:    b = 5 + 3 = 8
    // If fun1() evaluated first: b = 17 + 3 = 20
}
Key Fact
Java is the only language that guarantees left-to-right operand evaluation order, eliminating this ambiguity.
Referential Transparency (7.2.2.2)

A program is referentially transparent if any two expressions with the same value can be substituted for one another anywhere in the program without changing its behavior.

Example
// If fun(a) has NO side effects, these are equivalent:
result1 = (fun(a) + b) / (fun(a) - c);

temp = fun(a);
result2 = (temp + b) / (temp - c);
// result1 == result2 ✓

// If fun(a) modifies b or c as a side effect:
// result1 ≠ result2 → referential transparency violated ✗
Pure functional languages are referentially transparent by nature — no mutable variables
Makes programs much easier to reason about and understand
7.3
Overloaded Operators
// language-defined · user-defined · dangers
What is Operator Overloading?

Using the same operator symbol for multiple purposes. Every language does this to some extent.

Language-defined overloading example
3 + 4         // integer addition
3.0 + 4.0     // float addition
"hello" + "world"  // string concatenation (Java, Python)
User-Defined Overloading

Some languages let programmers define their own meanings for operators.

Example — matrix operations in C++
// With user-defined overloading for matrix type:
A * B + C * D

// Instead of:
MatrixAdd(MatrixMult(A, B), MatrixMult(C, D))
LanguageUser-Defined Overloading?
C++, C#, F#✅ Yes
Java❌ No — deliberately excluded
Ruby✅ Yes — operators are methods, can be overridden
Dangers of Overloading
Nothing stops you from defining + to mean multiplication — hurts readability
C++'s & is a bad example: binary & = bitwise AND, unary & = address-of operator. Two unrelated meanings.
Reader must find type definitions (possibly in other files) to understand an overloaded operator's meaning
C++ dangerous example
x = &y;   // unary & = address-of operator
x & y;    // binary & = bitwise AND
// Same symbol, completely unrelated meanings
7.4
Type Conversions
// widening · narrowing · coercion · explicit casts · errors
Widening vs Narrowing
Widening — converts to a type that can hold all original values. Generally safe. e.g. int → float
Narrowing — converts to a type that cannot hold all original values. Potentially dangerous. e.g. double → int
Gotcha
Even widening isn't always perfectly safe. Converting int to float: int has 9 decimal digits of precision, float has only ~7. Two digits of precision can be lost.
Coercion — Implicit Conversion (7.4.1)

Coercion is an implicit type conversion done automatically by the compiler. Enables mixed-mode expressions (operands of different types).

Example — coercion in Java
int a;
float b, c, d;
d = b * a;  // a is coerced to float automatically
// Danger: if 'a' was a typo for 'c', compiler won't catch it!
LanguageMixed-Mode Expressions
C, C++, Perl, JavaAllowed — coercion applied freely
Ada, ML, F#❌ Not allowed — stricter, safer
Special Rule — C-based languages
Types smaller than int (like byte, short in Java) are always coerced up to int when any operator is applied.
Explicit Type Conversion / Casts (7.4.2)

Programmer manually forces a conversion. Narrowing conversions require this in most languages.

Syntax by language
// C-based languages — type in parentheses
(int)angle

// F# and ML — looks like a function call
float(sum)
Errors in Expressions (7.4.3)

These are runtime errors, also called exceptions:

Overflow — result too large to store
Underflow — result too small (floating-point)
Division by zero — mathematically undefined, causes runtime exception
7.5
Relational & Boolean Expressions
// relational operators · boolean operators · C's special case
Relational Expressions (7.5.1)

Compares two operands and produces a Boolean result. Relational operators always have lower precedence than arithmetic operators.

Example
a + 1 > 2 * b
// Arithmetic is evaluated first, then comparison
// Equivalent to: (a+1) > (2*b)
LanguageSpecial Relational Behavior
JavaScript, PHP=== and !== compare without coercion. "7" == 7 is true, "7" === 7 is false.
Ruby== uses coercion, eql? does not
Boolean Expressions (7.5.2)

Combine Boolean values using AND, OR, NOT. In C-based languages, AND has higher precedence than OR.

Precedence in C-based languages (highest → lowest)
postfix ++, --
unary +, unary -, prefix ++, --, !
*, /, %
binary +, binary -
<, >, <=, >=
==, !=
&&
||
C's Special Case — No Boolean Type (before C99)

Older C had no Boolean type. Numeric values represent Boolean: 0 = false, any nonzero = true.

Tricky legal expression in C
a > b > c
// Does NOT check if b is between a and c!
// Step 1: (a > b) evaluates to 0 or 1
// Step 2: that result is compared with c
// b and c are never directly compared!

// Correct way to check b is between a and c:
(a > b) && (b > c)
7.6
Short-Circuit Evaluation
// early termination · array bounds · side effect dangers
What is Short-Circuit Evaluation?

The result is determined without evaluating all operands when the outcome is already clear.

If left operand of && is false → right operand is skipped (whole expression is false)
If left operand of || is true → right operand is skipped (whole expression is true)
Classic Array Bounds Example
Safe loop using short-circuit
index = 0;
while ((index < listlen) && (list[index] != key))
    index = index + 1;

// When index == listlen (key not found):
// With short-circuit: second condition skipped → safe ✓
// Without short-circuit: list[listlen] accessed → crash ✗
Language Support
LanguageShort-Circuit?Notes
Java✅ Yes&& and ||
C, C++✅ Yes&& and || are short-circuit. But & and | (bitwise) are NOT.
Ruby, Perl, ML, F#, Python✅ YesAll logical operators are short-circuit
Danger — Side Effects & Short-Circuit

If short-circuit skips a part of the expression that contains a side effect, that side effect may not always execute.

Example
(a > b) || ((b++) / 3)
// If a > b is true, b++ never executes
// If program depends on b being incremented every time → bug!
7.7
Assignment Statements
// simple · conditional targets · compound · unary · as expression · multiple · functional
Simple Assignment (7.7.1)

Most languages use =. ALGOL 60 and Ada use := to avoid confusion with the equality operator.

Conditional Targets (7.7.2)

Unique to Perl — the left-hand side of an assignment can be conditional.

Example
($flag ? $count1 : $count2) = 0;
// Equivalent to:
if ($flag) { $count1 = 0; }
else        { $count2 = 0; }
Compound Assignment Operators (7.7.3)

Shorthand when destination variable also appears as the first operand on the right. Introduced by ALGOL 68, adopted by C and most C-based languages, Perl, JavaScript, Python, Ruby.

Example
sum += value;    // same as: sum = sum + value
a   *= b;        // same as: a = a * b
x   -= 1;        // same as: x = x - 1
Unary Assignment Operators (7.7.4)

Available in C-based languages, Perl, JavaScript. Combine increment/decrement with assignment. Prefix vs postfix matters.

Prefix vs Postfix
sum = ++count;  // count incremented FIRST, then assigned to sum
sum = count++;  // assigned to sum FIRST, then count incremented

// When two unary operators on same operand → right to left:
-count++        // means -(count++) NOT (-count)++
Assignment as an Expression (7.7.5)

In C-based languages, Perl, JavaScript — assignment produces a value and can be used inside other expressions.

Useful example
while ((ch = getchar()) != EOF) { ... }
// ch is assigned, then compared with EOF in same expression
Danger
if (x = y)   // assigns y to x, tests value — NO compiler error!
if (x == y)  // this is what you meant
Java and C# avoid this by requiring boolean expressions in if statements.
Multiple Assignments (7.7.6)

Available in Perl and Ruby. Multiple targets and sources in one statement.

Example — Perl
($first, $second, $third) = (20, 40, 60);

// Swap without a temp variable:
($first, $second) = ($second, $first);
Assignment in Functional Languages (7.7.7)

In pure functional languages, identifiers are names bound to values — they never change. There is no traditional assignment.

ML — val binding
val cost = quantity * price;
// Not a variable — a name permanently bound to a value
// A second 'val cost' creates a NEW binding, hiding the old one
ML's val — binds a name, does NOT create a new scope
F#'s let — similar to val but DOES create a new scope
In ML, val declarations are often nested inside let constructs
7.8
Mixed-Mode Assignment
// coercion rules per language
The Design Question

Does the type of the expression have to match the type of the variable, or can coercion be applied on assignment?

LanguageMixed-Mode Assignment Rule
C, C++, PerlCoercion freely applied. Many type mixes legal.
Java, C#Only widening coercions allowed. Narrowing needs explicit cast.
Ada, ML, F#No mixed-mode assignment at all. Types must match exactly.
Python, RubyConcept doesn't apply — types belong to objects, not variables.
Example — Java
int x = 5;
float y = x;       // ✓ legal — widening coercion
int z = y;         // ✗ illegal — narrowing, needs cast
int z = (int) y;   // ✓ legal — explicit narrowing cast
Design Intent
Java and C#'s restriction to widening-only is a deliberate reliability improvement over C/C++, reducing the risk of undetected type errors.
