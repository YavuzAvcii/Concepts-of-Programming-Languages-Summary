§ 5.2

Names

A name (identifier) is a string of characters used to identify a program entity. Key design issues are case sensitivity and whether special words are reserved words or keywords.

§ 5.4

Binding & Binding Times

A binding is an association between an entity and an attribute. The moment this association is established is the binding time.

§ 5.4.3

Storage Bindings & Variable Lifetime

The lifetime of a variable is the time between when it is bound to storage and when it is unbound. Four categories:

CategoryAllocationDeallocationLanguagesAdvantagesDisadvantages
Static Before execution begins After execution ends Global vars (C/C++/Java), static locals in C/C++ +direct addressing +history-sensitive -no recursion -no storage sharing
Stack-dynamic At declaration elaboration (subprogram call) When subprogram returns Local vars in Java, C++, C# methods +supports recursion +shared stack space -not history-sensitive -indirect addressing overhead
Explicit heap-dynamic By explicit programmer instruction (new) By delete or GC C++ (new/delete), Java objects, C# objects +dynamic structures (linked lists, trees) -complex management -pointer errors
Implicit heap-dynamic On assignment By GC JavaScript, Python lists assigned dynamically +maximum flexibility -run-time overhead -less error detection 
// C++ — all four categories in one example
int global_x = 0;               // static (global)

void demo() {
    static int call_count = 0;  // static (local)
    int local_y = 5;            // stack-dynamic
    int* heap_z = new int(10);  // explicit heap-dynamic
    delete heap_z;
}

// JavaScript — implicit heap-dynamic
highs = [74, 84, 86, 90];       // bound to array type on assignment
§ 5.5

Scope

The scope of a variable is the range of program statements in which it is visible (can be referenced or assigned).

local
Declared in the current program unit or block.
nonlocal
Visible but declared in an outer unit.
global
Special nonlocal: defined outside all functions/subprograms.

Static (Lexical) Scoping

Introduced by ALGOL 60. Scope is determined from the text of the program — before execution. To resolve a nonlocal variable, search proceeds outward through static ancestors (enclosing subprograms).

Languages with nested subprograms: Ada, JavaScript, Python, F#, Common Lisp, Scheme, Fortran 2003+

Languages without nested subprograms (C-based): C, C++, Java, C#

function big() {
    var x = 3;              // big's x
    function sub1() {
        var x = 7;          // sub1's own x (hides big's x)
        sub2();
    }
    function sub2() {
        var y = x;          // resolves to big's x = 3
    }                       // (sub1's x is NOT a static ancestor of sub2)
    sub1();
}
Key rule: If a variable name is not found in the local scope, search continues in the static parent, then its parent, etc. A declaration in a closer scope hides the same-named variable in an outer scope.
§ 5.5.2

Blocks & Declaration Order

A block is a compound statement that can define its own local scope (introduced by ALGOL 60). Variables in a block are typically stack-dynamic.

// C — block scope example
if (list[i] < list[j]) {
    int temp;           // temp lives only inside this block
    temp = list[i];
    list[i] = list[j];
    list[j] = temp;
}

§ 5.5.6

Dynamic Scoping

In dynamic scoping, nonlocal variable resolution is based on the calling sequence at run time, not source text. To find a variable, search the current local scope, then the calling function, then its caller, etc.

Languages: APL, SNOBOL4, early Lisp; optional in Perl & Common Lisp.

// Same big() example — different result under dynamic scoping:
function big() {
    var x = 3;
    function sub1() { var x = 7; sub2(); }
    function sub2() { var y = x; }   // which x?
    sub1();
}
// Call chain: big → sub1 → sub2
//   Dynamic: x found in sub1 → x = 7
// Call chain: big → sub2 (directly)
//   Dynamic: x found in big → x = 3

§ 5.6

Scope vs. Lifetime

These are related but distinct concepts: scope is spatial/textual; lifetime is temporal.

Example: A C++ static local has local scope (only visible inside its function) but its lifetime spans the entire program execution.

Example: When compute() calls printheader(), the variable sum (declared in compute) is not in scope inside printheader, but it is still alive (its storage persists) during printheader's execution.
§ 5.7

Referencing Environments

The referencing environment of a statement is the set of all variables visible to that statement.

  • Static-scoped language: local vars + all visible vars from ancestor scopes.
  • Dynamic-scoped language: local vars + vars of all currently active subprograms.
// Dynamic scoping example — main calls sub2, sub2 calls sub1
void sub1() { int a, b; /* point 1 */ }
void sub2() { int b, c; /* point 2 */ sub1(); }
void main() { int c, d; /* point 3 */ sub2(); }

// Referencing environments:
// Point 1: a,b(sub1)  c(sub2)  d(main)  [c of main & b of sub2 hidden]
// Point 2: b,c(sub2)  d(main)            [c of main hidden]
// Point 3: c,d(main)
§ 5.8

Named Constants & Initialization

A named constant is a variable bound to a value exactly once. Benefits: readability, program parameterization (change value in one place).

LanguageSyntaxBinding timeNotes
Javafinal int X = expr;Dynamic (any expr)Can be set later via assignment
C++const int X = expr;Dynamic (any expr)Expression evaluated at declaration
C# constconst int X = literal;Compile time (static)Only literals/const expressions allowed
C# readonlyreadonly int X = expr;DynamicSet in declaration or static constructor
Initialization: binding a value to a variable at the same time it is bound to storage. If storage is static → initialization before run time (must use literals/const). If storage is dynamic → initialization is also dynamic.
§ Review

Review Questions & Answers

Click a question to reveal the answer, or toggle all at once.

  1. What are the design issues for names?
    Two main design issues: (1) Case sensitivity — are uppercase and lowercase versions of the same letter treated as the same character? (2) Reserved words vs. keywords — can special words be redefined by programmers (keywords) or not (reserved words)?
  2. What is the potential danger of case-sensitive names?
    Names that look similar (e.g. Rose and rose) actually denote completely different entities. This violates the readability principle that similar-looking constructs should have similar meanings. It is also a writability problem: programmers must remember exact capitalisation (e.g. Java's parseInt vs. ParseInt).
  3. What is an alias?
    An alias exists when two or more variable names refer to the same memory location. Changing one alias inadvertently changes the other, harming readability and making program verification more difficult. Aliases are created via pointer/reference assignment, C/C++ unions, or certain parameter passing mechanisms.
  4. Which category of C++ reference variables always produces aliases?
    Pointer variables (and reference variables) create aliases whenever two of them point to the same memory location. Specifically, when a C++ pointer is set to point to a named variable, the dereferenced pointer and the variable name are aliases.
  5. What is the l-value of a variable? What is the r-value?
    l-value: the address (memory location) of a variable — what is needed when the variable appears on the left side of an assignment. r-value: the contents (value) of that memory location — what is needed when the variable appears on the right side of an assignment.
  6. Define binding and binding time.
    A binding is an association between an attribute and a program entity (e.g., a variable and its type, or an operator and its meaning). The binding time is the moment at which that association is established (language design time, implementation time, compile time, link time, load time, or run time).
  7. After language design and implementation, what are the four times bindings can take place?
    1. Compile time — e.g., type of a Java variable. 2. Link time — e.g., a library call bound to its code. 3. Load time — e.g., a global variable bound to a storage address. 4. Run time — e.g., a variable's value, or a heap-dynamic variable's storage.
  8. Define static binding and dynamic binding.
    A binding is static if it first occurs before run time and remains unchanged throughout program execution. A binding is dynamic if it first occurs during run time or can change during execution.
  9. What are the advantages and disadvantages of implicit declarations?
    Advantage: Minor programmer convenience — no need to write explicit type declarations for every variable. Disadvantages: Reduced reliability, because the compiler cannot detect typographical or type errors (a misspelled variable name simply creates a new variable instead of producing an error).
  10. What are the advantages and disadvantages of dynamic type binding?
    Advantages: Greater flexibility — generic programs can handle data of any type; no need to know types at write time. Disadvantages: (1) Less reliable — type errors not caught at compile time; (2) Higher cost — type checking at run time, every variable needs a run-time type descriptor, requires an interpreter (typically ≥10× slower than compiled code).
  11. Define static, stack-dynamic, explicit heap-dynamic, and implicit heap-dynamic variables, with advantages and disadvantages.
    Static: bound before execution begins, lives for entire run. + efficient (direct addressing), history-sensitive. − no recursion, no storage sharing.

    Stack-dynamic: allocated on call, deallocated on return. + supports recursion, subprograms share memory. − not history-sensitive, indirect addressing overhead.

    Explicit heap-dynamic: allocated/deallocated explicitly by programmer (new/delete). + enables dynamic structures. − error-prone, complex memory management.

    Implicit heap-dynamic: all attributes bound at every assignment. + maximum flexibility. − high run-time overhead, loss of compile-time error detection.
  12. Define lifetime, scope, static scope, and dynamic scope.
    Lifetime: the period from when a variable is bound to storage until it is unbound.
    Scope: the range of program statements in which a variable is visible.
    Static scope: scope determined from source-code text before execution; search for a nonlocal goes to the textual (static) parent.
    Dynamic scope: scope determined by the calling sequence at run time; search for a nonlocal follows the call chain.
  13. How is a reference to a nonlocal variable in a static-scoped program connected to its definition?
    The compiler searches the declarations of the current (local) subprogram first. If no declaration is found, it searches the static parent (the subprogram that syntactically/textually contains the current one), then the static parent's parent, and so on up to the outermost program unit. The first matching declaration found is the one used; if none is found, an undeclared variable error is reported.
  14. What is the general problem with static scoping?
    Two main problems: (1) It allows more access to variables and subprograms than is actually necessary — it is too coarse-grained a tool. (2) It can be undermined by program evolution: as programs change over time, developers work around static-scope access restrictions by making variables global or flattening nesting, leading to designs that diverge from the original clean structure.
  15. What is the referencing environment of a statement?
    The collection of all variables that are visible in that statement. In a static-scoped language it consists of the local variables plus all visible variables from ancestor scopes. In a dynamic-scoped language it consists of the local variables plus variables in all currently active subprograms (those that have started but not yet terminated).
  16. What is a static ancestor vs. a dynamic ancestor of a subprogram?
    A static ancestor is any subprogram that textually encloses the given subprogram in the source code (static parent, grandparent, etc.). A dynamic ancestor is any subprogram that is currently active in the call chain (i.e., has been called but not yet returned) — the calling function, its caller, etc.
  17. What is a block?
    A block is a section of executable code (typically a compound statement enclosed in braces or keywords) that can define its own local variables, creating a new static scope. Introduced in ALGOL 60. Local variables in blocks are stack-dynamic — allocated on entry, deallocated on exit.
  18. What is the purpose of the let constructs in functional languages?
    A let construct creates a local scope in which names are bound to values (expressions). It mirrors the role of a block in imperative languages. The bound names are immutable (like named constants), unlike variables in imperative blocks. The final part of a let is an expression whose value is the result of the whole construct (e.g., Scheme's LET, ML's let…in…end).
  19. What is the difference between names in an ML let construct and variables declared in a C block?
    In an ML let, names are bound to values once and cannot be changed — they act like named constants. In a C block, declared variables are mutable; their values can be changed repeatedly by assignment statements throughout the block's execution.
  20. Describe the encapsulation of an F# let inside a function and outside all functions.
    Outside all functions: a let name is a global whose scope extends from its definition to the end of the file. Inside a function: the scope of a let extends from after its defining expression to the end of the function. Indenting subsequent code creates a nested local scope that ends when the indentation ends — names defined in the nested scope are not visible outside it.
  21. What are the advantages and disadvantages of dynamic scoping?
    Advantage: Parameters defined in a calling subprogram do not need to be explicitly passed to called subprograms — they are implicitly visible. Disadvantages: (1) Nonlocal variables cannot be statically type-checked; (2) Programs are harder to read (must trace the call chain); (3) Local variables are exposed to all called subprograms — no protection; (4) Nonlocal access is slower (runtime search required).
  22. What are the advantages of named constants?
    (1) Readability — a meaningful name (e.g., PI) is clearer than a bare literal. (2) Modifiability (parameterization) — changing the constant in one place updates it everywhere it is used, reducing errors and tedium. (3) Reliability — the compiler can prevent accidental mutation of the value.
